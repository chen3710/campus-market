# 简历话术：怎么把这个项目写进简历

> 这份文档解决一个问题：**你已经把项目做出来了，但简历上那三行字该怎么写，才能让 HR 不划走、让面试官想追问。**
>
> 配套阅读：[`面试讲点.md`](面试讲点.md)（面试时的口头讲法）。

---

## 一、先明确：这个项目在简历里扮演什么角色

校招简历通常只有 1 页，项目部分占 1/3 到 1/2。你有两种选择：

| 你的情况 | 建议 |
|---|---|
| 只有这一个像样的项目 | 作为**主项目**展开写，4~5 条 bullet，占项目区 2/3 |
| 还有实习/竞赛项目 | 这个作为**技术亮点项目**，3 条 bullet 即可，把篇幅让给实习 |

**关键认知：简历上的项目描述不是"介绍项目做了什么"，而是"给面试官递刀子"。**
每一条 bullet 都应该是一个**可以被追问、而你已经准备好答案**的技术点。写一条你答不上来的，等于给自己挖坑。

---

## 二、项目描述模板（Java 后端岗 · 推荐版）

直接可用的写法，已按真实实现核对过，没有夸大：

```
校园二手交易平台（个人项目）                                    2026.09
技术栈：Spring Boot 3.3 / MyBatis-Plus / MySQL 8 / JWT / 原生 HTML+CSS+JS

· 独立完成 8 张表的库表设计与全部前后端代码（75 个 Java 文件 + 9 个前端文件），实现商品发布、下单、
  订单流转、收藏留言、信用分与后台管理六大模块，共 29 个 REST 接口。

· 针对并发下单超卖问题，放弃「先查询再更新」的写法，改用带版本号的条件更新
  （CAS）把「判断在售」与「锁定商品」压成一条 SQL，依赖 InnoDB 行锁保证原子性；
  用 10 线程并发脚本压测验证，同一商品 10 个请求恰好只有 1 个下单成功。

· 用「枚举 + 状态流转表」实现订单状态机，把非法流转（如已取消订单被再次确认）
  收敛到一处拦截，并由状态机反推前端可操作按钮，替代散落各处的 if-else 判断。

· 用 @Scheduled 定时任务实现订单超时自动取消，解决「卖家迟迟不确认导致商品被
  僵尸订单永久锁死」的问题；针对定时任务与用户操作的并发竞争改用 CAS 保证只有
  一方生效，并将事务粒度定为单笔订单（独立 Bean，规避同类内调用绕过 @Transactional
  代理而静默失效的坑）。

· 基于 JWT + 拦截器 + 自定义注解（@LoginRequired / @AdminOnly）实现无状态鉴权，
  取代 URL 白名单配置；用 ThreadLocal 传递登录上下文并在请求结束时强制清理。

· 商品列表通过 LEFT JOIN 一次取全卖家与分类信息，收藏状态用一次 IN 批量查询，
  消除 N+1；SQL 数量恒定不随记录数增长（登录态 2 条、匿名 1 条）。
  排序参数走白名单枚举而非字符串拼接，规避 ORDER BY 注入。

· 编写 53 项 JVM 内自动化测试（25 项单元测试覆盖订单状态机完整流转矩阵 +
  28 项 MockMvc 接口集成测试覆盖鉴权与状态码语义），另有 108 项真实 HTTP
  冒烟断言（含并发防超卖、越权访问、信用分结算），并借助无头浏览器验证
  前端 6 个页面无 JS 运行时错误。
```

**为什么这样写有效：**

- 每条都是 **"遇到什么问题 → 用了什么方案 → 怎么验证的"**，而不是罗列技术名词。
- 每条都埋了追问点（CAS 为什么行、状态机怎么设计、JWT 为什么要清理 ThreadLocal），而这些在 `面试讲点.md` 里都有现成答案。
- 数字全部真实可复现（113 个文件、53 项自动化测试、108 项断言、10 线程），面试官真让你跑你也跑得出来。

### 另一种排版：标准简历条目格式

有些简历模板或校招系统要求按固定字段填（【项目时间】【技术栈】【项目地址】【项目描述】【个人职责】【项目成果】）。
照下面这段填，**每一句都能在代码里指出对应位置**：

```
校园二手交易平台（个人项目）

【项目时间】2026.09
【技术栈】Spring Boot 3.3.7 + MyBatis-Plus 3.5.7 + MySQL 8.0 + JWT + Lombok + 原生 HTML/CSS/JS

【项目地址】https://gitee.com/<你的账号>/campus-market.git

【项目描述】
基于 Spring Boot 开发的校园二手交易平台，后端提供 RESTful 接口，搭配原生 HTML/CSS/JS
前端页面，实现商品发布、订单交易、收藏留言、信用分结算、后台管理等核心功能，支持多
用户在线交易，并针对并发下单场景做了防超卖处理。

【个人职责】
1. 负责后端整体架构设计：采用标准三层架构（Controller / Service / Mapper），基于
   MyBatis-Plus 实现数据库交互与分页查询，统一响应体与全局异常处理，错误码语义化
   （400 参数校验 / 401 未登录 / 403 越权 / 404 资源不存在 / 409 状态冲突 / 422 业务规则拦截）
2. 实现用户模块：完成注册、登录、资料管理、信用分流水等接口，密码采用 BCrypt 加密
   存储；基于 JWT + 拦截器 + 自定义注解（@LoginRequired / @AdminOnly）实现无状态鉴权，
   取代 URL 白名单配置，并用 ThreadLocal 传递登录上下文、在请求结束时强制清理
3. 核心交易链路开发：基于带版本号的条件更新（CAS）把「判断在售」与「锁定商品」压成
   一条 SQL，解决并发下单超卖；用「枚举 + 状态流转表」实现订单状态机，非法流转集中拦截
4. 数据库设计与查询优化：设计用户、商品、订单、收藏、留言等 8 张核心表；通过 LEFT JOIN
   与批量 IN 查询消除 N+1，列表接口 SQL 数量恒定不随记录数增长；排序参数走白名单枚举，
   规避 ORDER BY 注入
5. 订单超时自动取消：基于 @Scheduled + fixedDelay 实现定时清理，解决「卖家迟迟不确认
   导致商品被僵尸订单永久锁死」；用 CAS 处理定时任务与用户操作的并发竞争，并把事务方法
   抽为独立 Bean，规避同类内调用绕过 @Transactional 代理而静默失效的坑

【项目成果】
1. 实现完整交易闭环（发布 → 下单锁定 → 卖家确认 → 买家完成 → 信用分结算），10 线程
   并发下单同一商品时恰好 1 个成功、其余返回冲突，防超卖逻辑经真实压测验证
2. 建立四层验证体系：53 项 JVM 内自动化测试（25 项单元测试覆盖订单状态机完整流转矩阵
   + 28 项 MockMvc 集成测试覆盖鉴权与状态码语义）+ 108 项真实 HTTP 冒烟断言 + 无头浏览器
   前端渲染验证
3. 项目配套完整 README（含系统架构图、下单链路时序图、数据库 ER 图），并内置 H2 内存库
   模式，无需安装 MySQL 即可一键运行
```

**如果简历空间紧张**，把「个人职责」第 4、5 条合并成一条即可（都属数据层/稳定性），
保留 1、2、3 这三条主干。

**填写时必须注意的 4 件事：**

| 字段 | 注意点 |
|---|---|
| 【项目时间】 | **别照抄示例**。写你真实的开发周期。如果实际只有几天，不必硬撑成三个月——面试官会追问每个阶段做了什么，答不上来反而减分。一个人几天做完一个完整可运行项目，本身就是能力证明。 |
| 【项目地址】 | 推送前**先把 git 提交身份改成你的真实姓名和邮箱**（当前是占位的 `campus-market <dev@example.com>`），否则提交记录一看就是模板生成。 |
| 【技术栈】 | **不要加 Docker / Redis / 消息队列 / Elasticsearch**。项目里没有，面试官一追问就露馅。技术栈只写 pom.xml 里真实存在的。 |
| 【个人职责】 | 只写你真的做过的。上面 5 条分别对应 `ProductMapper`（CAS）、`OrderStatus`（状态机）、`JwtInterceptor`（鉴权）、`ProductMapper.xml`（JOIN）、`OrderTimeoutScheduler`（定时任务），都能现场打开代码指给面试官看。 |

## 三、按岗位调整侧重

同一份代码，投不同岗位时该把哪条放前面、写多细，是不一样的。

### 投 Java 后端

保留上面全部 6 条。**重点加粗第 2、3、4、5 条**（CAS / 状态机 / 鉴权 / N+1 与注入）。

删掉第 6 条里"前端 6 个页面无 JS 错误"的表述，改成「编写 108 项接口冒烟测试」——后端岗更关心你**会不会验证自己的代码**，而不是前端跑不跑得起来。

### 投全栈 / 前端偏重的岗位

把前端那条从"附带"提到"独立 bullet"：

```
· 前端采用原生 HTML/CSS/JS 实现 6 个页面，不引入任何框架与构建工具，
  由 Spring Boot 直接托管静态资源，克隆下来零配置即可运行。

· 用 CSS 变量集中管理设计系统（主色、间距、圆角、阴影），保证 6 个页面视觉一致；
  封装 escapeHtml 统一处理用户输入渲染，规避 DOM 型 XSS。
```

**这样写的好处**：说明你不是"不会框架才用原生"，而是**主动做了技术选型**（小项目引入 Vue/React + 构建链，收益低于复杂度成本）。这个理由要在面试时讲出来。

### 投测试 / 质量方向

把测试那条提到第一位，并展开：

```
· 设计并实现四层验证体系：25 项单元测试（纯逻辑，毫秒级）+ 28 项 MockMvc
  接口集成测试（JVM 内覆盖鉴权、参数校验、状态码语义与响应契约）+ 108 项
  真实 HTTP 冒烟断言 + 无头浏览器渲染验证（抓 JS 运行时错误）。
· 测试过程中发现并修复 3 个真实缺陷：业务错误码误用 500 导致与系统异常混淆、
  下单接口权限语义错误返回 500、响应体因序列化多出冗余字段。
```

**"测试抓出真实 bug"这个细节比"写了多少测试"更有说服力**——它证明测试不是走过场。

如果面试官追问「单元测试和集成测试的边界怎么划」，可以答：

> 我按**是否需要外部资源**来划。纯逻辑（状态机、流转矩阵）零依赖，放单元测试，跑得最快；一旦要经过 Spring MVC 的拦截器、参数绑定、异常处理，就放 MockMvc —— 它不依赖数据库和端口，但能走完整条 Servlet 链路；只有真数据库事务、真并发这种**必须真实环境才能暴露**的问题，才留给 shell 冒烟脚本。**能用便宜的层测，就绝不放到贵的层。**

## 四、可量化的成果怎么写（不要写"提升了性能"）

校招简历最容易犯的错是编造性能数据（"QPS 提升 300%""响应时间降低 80%"）。
你单机跑的项目，面试官一问测试环境就露馅。

**用结构性事实代替性能数字**：

| ❌ 别这么写 | ✅ 改成这么写 | 依据 |
|---|---|---|
| 优化了数据库查询性能 | 通过 LEFT JOIN 与批量 IN 查询消除 N+1，商品列表固定 1 次 SQL 取全 | 看 `ProductMapper.xml` |
| 系统支持高并发 | 10 线程并发下单同一商品，恰好 1 个成功，9 个返回 409 | 跑 `smoke-test.sh` 第 6 节「并发抢单」 |
| 提高了代码可维护性 | 订单状态流转收敛为一张流转表，非法流转集中拦截并返回 422 | 看 `OrderStatus.java` |
| 做了完善的测试 | 53 项 JVM 内自动化测试（25 单元 + 28 MockMvc）+ 108 项接口断言，覆盖状态机完整流转矩阵 | `./mvnw test` 可复现 |
| 增强了系统安全性 | 密码 BCrypt 加密 + 排序参数白名单 + 上传扩展名白名单与路径逃逸校验 | 三处代码可指 |

**核心原则：写"我做了什么结构上的改变"，而不是"我的系统有多快"。**
前者可验证、可追问、可深挖；后者只会招来"你压测环境是什么"这种你答不好的问题。

## 五、绝对不要写的话

| 不要写 | 原因 | 改成 |
|---|---|---|
| 熟悉 Spring Boot / MySQL | 太空泛，等于没写 | 写具体做了什么，如"用 MyBatis-Plus 的 Wrapper + XML 混合处理单表与多表" |
| 精通 Java | 校招写"精通"是减分项 | 用"熟练使用"，或干脆不写程度副词 |
| 高并发 / 分布式 / 微服务 | 这是单机项目，写了必被追问 | 写"并发下单场景"，并准备好讲 CAS |
| 采用 Redis 缓存优化性能 | 项目里没有 Redis | 删掉。想加就真去加，然后写 |
| 参与需求分析与系统设计 | 个人项目没有"参与" | 写"独立完成库表设计与接口设计" |
| 良好的团队协作能力 | 个人项目谈协作很怪 | 删掉，放进自我评价而非项目描述 |

**一条铁律：简历上每一个技术名词，都要能扛住三层追问。**
写"JWT 鉴权"就要能答：为什么不用 Session？Token 过期怎么处理？登出怎么实现？

## 六、每条 bullet 会被追问什么（提前准备）

| 简历上的写法 | 面试官最可能追问 | 答案在 |

| "JWT + 自定义注解" | 为什么不用 Spring Security？Token 怎么失效？ThreadLocal 不清理会怎样？ | 面试讲点 §3 |
| "消除 N+1 查询" | 什么是 N+1？你怎么发现的？LEFT JOIN 和两次查询哪个好？ | 面试讲点 §4 |

| "108 项冒烟测试" | 并发那条怎么保证稳定复现？会不会 flaky？ | 面试讲点 §10 |

## 七、如果面试官只有 30 秒看简历

HR 初筛和面试官快速扫简历时，只会抓关键词。**你最希望他看到的三个词：**

1. **防超卖 / 乐观锁 / CAS** —— 证明你碰过并发，不是纯 CRUD
2. **状态机** —— 证明你会用设计模式收敛复杂逻辑
3. **161 项测试**（53 项 JVM 内自动化 + 108 项真实 HTTP 冒烟）—— 证明你会验证自己的代码

所以**这三条要放在 bullet 的最前面，并且把关键词写在句首**，不要埋在长句中间。

## 八、投递前的自查清单

- [ ] 项目名称后面标了「个人项目」，避免被误会成公司项目
- [ ] 技术栈里的每一个名词，我都能讲 3 分钟
- [ ] 每一条 bullet 都是"问题 → 方案 → 验证"，不是名词堆砌
- [ ] 所有数字都能在项目里复现（文件数、测试数、并发数）
- [ ] 没有出现 Redis / MQ / 微服务等**项目里不存在**的技术
- [ ] 已经通读过一遍 `面试讲点.md`，每条追问都有答案
- [ ] 简历上的项目能在本地跑起来（面试官可能让你现场演示）

> 最后一条特别重要：**面试前把项目在你自己的电脑上跑通一遍**。
> 用 `./mvnw spring-boot:run -Dspring-boot.run.profiles=h2` 就能起（不需要装 MySQL），
> 演示账号见 README。万一面试官说"你打开我看看"，你能立刻打开，这是很大的加分。
